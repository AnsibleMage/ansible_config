## 아키텍처 질문 5가지

### Q1. Hook 시스템이 필요한가?

**데이터**:
- Hook 체인 추천 정확도: 38.5% (13건 중 5건만 매칭)
- Hook이 GameDevChain을 18건 중 8건(44%)에서 추천했지만 실제 사용은 2건(11%)
- 네가 Hook 추천을 무시하고 자율 판단한 경우가 더 정확했다

**그러나**: 원래 Hook을 만든 이유는 **네가 체인을 스스로 선택하지 않았기 때문**이다. Hook이 additionalContext로 체인/에이전트 추천을 주입하니까 그제서야 네가 체인을 의식하고 선택하기 시작했다. Hook을 제거하면 다시 체인을 무시할 가능성이 있다.

**네가 판단해야 할 것**: Hook의 역할을 "정확한 추천자"에서 **"체인 활성화 촉매(catalyst)"**로 재정의하는 것이 맞는지. 즉, Hook이 틀려도 괜찮다 — Hook이 "체인이라는 것이 존재한다"를 상기시켜주는 역할만 해도 가치가 있는지.

결론을 내리고, Hook 시스템의 역할을 CLAUDE.md Section 2.1에 명확히 재정의하라. 구체적으로:
- Hook이 틀린 추천을 했을 때 네가 어떻게 해야 하는지 **의사결정 프로세스를 Section 2.2에 명시**하라
- 예: `Hook 추천 수신 → 아리 자체 분석 → 일치하면 실행 / 불일치하면 아리 판단 우선 (근거 명시)`

**중요**: Q1의 결론은 Q2(축약), Q3(Teams)에 영향을 준다. Q1을 먼저 확정하라.

### Q2. 체인 축약이 적절한가?

**데이터**:
- 에이전트 평균 실행율: 61.8% (체인 정의 대비)
- quality_reviewer만 100% 호출 (4/4)
- MetaThinkChain 8단계 → 항상 3단계로 축약 (37.5%)
- ResearchChain 4단계 → 항상 1단계로 축약 (25%)

**질문**: 이 에이전트들이 정말 필요한가? 체인 정의가 과도한 건 아닌가? 아니면 네가 너무 일찍 "충분하다"고 판단하는 건가?

**네가 판단해야 할 것**:
1. 현실에 맞게 체인을 슬림화할지 (MetaThinkChain 8→3~4)
2. 아니면 축약 조건을 명시화할지 (예: `[optional]` 태그로 "분석 깊이 부족 시에만 진행")

### Q3. Agent Teams 활성화율을 어떻게 올릴 것인가?

**데이터**:
- Teams 적합 체인에서의 활성화: 1/3 (33%) — T-11만 성공
- T-07(ResearchChain, 적합)에서 Teams 미사용 — "조사해줘"에 병렬 의도 약함
- T-11 성공 조건: "웹 + Roblox **동시에**" — 명시적 병렬 키워드

**현실**: Teams 전환이 프롬프트에 "동시에"가 있어야만 발동한다. 이러면 사용자가 항상 "동시에"를 써야 하는데, 그건 사용자 의존적이다.

**네가 판단해야 할 것**:
1. Section 2.5에 더 구체적인 자동 전환 조건을 추가할지
2. Hook이 Teams 적합성도 추천하도록 할지
3. 체인 선택 시점(Section 2.2)에서 Teams 분기를 자동 평가하도록 할지
4. 현실적으로 어떤 수준의 활성화율을 목표할지

### Q4. prompt_analyzer.py에 무엇을 수정할 것인가?

**데이터**:
- T-03: "멀티플레이어", "랭킹", "리더보드" 미등록 → 추천 0건 (❌ FAIL)
- T-05: 파일 경로 "Documents"→/docx 오탐, "Roblox"→GameDevChain 오탐
- T-09: "긴급"보다 "Roblox"가 우선 → HotfixChain 대신 GameDevChain 추천
- T-16: "버전"→번역 오탐 방지는 성공 ✅

**수정 범위**: 부록 B의 P0-2, P1-1, P1-2, P2-2, P2-3을 읽고 네 판단으로 통합 실행하라.

### Q5. 즉시 수정해야 할 것은 무엇인가?

다음 3가지는 아키텍처 판단 없이 즉시 수정 가능:

1. **에이전트 YAML 14개**: `description:` 필드의 `Use when:` 패턴 → YAML 파싱 실패 → `Total plugin agents loaded: 0`. 블록 스칼라(`|`)로 수정

## 수정 원칙 (반드시 지켜라)

### 범위 제한
- **수정 대상**: CLAUDE.md, prompt_analyzer.py, settings.json, ~/.claude/agents/*.md
- **수정하지 않을 것**: 체인 패턴 A~J의 기본 구조 (슬림화는 허용하되 체인을 새로 추가하거나 근본 구조를 변경하지 마라)
- **원천 요구사항**: CLAUDE.md V4.1.1이 원천이다. 이 문서의 Section 1~5의 **목적**을 벗어나는 수정을 하지 마라

### 주객전도 방지
2일간 지속적 버전업으로 시스템이 비대해졌다. 원래 목적을 기억하라:
- CLAUDE.md는 **너(아리)의 행동 규칙서**다 — 너를 위한 것이지, 시스템 자체를 위한 것이 아니다
- 체인은 **작업 품질을 높이는 도구**다 — 체인을 관리하는 것이 목적이 아니다
- Hook은 **너의 판단을 돕는 보조 시스템**이다 — Hook이 완벽할 필요 없다
- **이건 수정이 아니다 싶으면 하지 마라** — "있으면 좋겠다"는 scope creep이다. "없으면 테스트가 실패한다"만 수정하라

### 검증 가능성
모든 수정은 블라인드 재테스트로 검증할 것이다. 수정할 때 다음을 자문하라:
- "이 수정이 T-01~T-18 중 어떤 테스트의 결과를 개선하는가?"
- "답할 수 없으면 그 수정은 하지 마라"

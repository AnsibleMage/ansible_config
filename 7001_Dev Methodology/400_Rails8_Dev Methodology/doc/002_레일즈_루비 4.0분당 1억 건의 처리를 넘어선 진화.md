## 1. 개요: 루비의 새로운 전성기
루비는 전통적으로 높은 생산성(레일즈 프레임워크 기반)으로 유명했지만, 성능 면에서는 비판을 받기도 했습니다. 하지만 루비 4.0은 **쇼피파이(Shopify)**가 블랙프라이데이 기간 동안 **분당 1억 1,700만 건의 요청을 처리**할 정도로 압도적인 성능과 안정성을 증명하며, 다시 한번 현대 웹 개발의 강력한 스택으로 자리매김했습니다.

---

## 2. 3대 핵심 변화 (Major Updates)

### ① 새로운 JIT 컴파일러: ZJIT
* **배경:** 기존 YJIT가 코드 블록 단위로 컴파일했다면, ZJIT는 **메서드 전체를 한 번에 컴파일**합니다.
* **아키텍처:** 전통적인 컴파일러 이론인 **SSA(Static Single Assignment, 정적 단일 할당)** 형식을 중간 표현으로 사용하여 설계가 매우 정석적입니다.
* **의의:** 현재 성능은 YJIT가 우위에 있으나, ZJIT의 교과서적인 설계 덕분에 더 많은 오픈소스 개발자가 루비 코어에 기여할 수 있는 통로가 열렸습니다.
* **사용법:** `--zjit` 플래그로 활성화 가능.

### ② 격리된 네임스페이스: 루비 박스 (Ruby Box)
* **기능:** 하나의 애플리케이션 내에서 **같은 라이브러리의 서로 다른 버전을 동시에 로드**할 수 있는 격리 환경을 제공합니다.
* **해결 과제:** 이른바 '의존성 지옥(Dependency Hell)'과 몽키 패칭으로 인한 전역 오염 문제를 방지합니다.
* **활용:** 대규모 레거시 시스템에서 기존 코드를 유지하면서 새로운 모듈만 최신 라이브러리를 적용할 때 유용합니다.
* **사용법:** 환경 변수 `RUBY_BOX=1` 설정 시 활성화 (현재 실험적 기능).

### ③ 렉터(Ractor) API 전면 재설계
* **목표:** 루비의 고질적 한계였던 **GIL(Global Interpreter Lock)**을 우회하여 멀티코어 CPU를 완벽하게 활용하는 **진정한 병렬 처리** 구현.
* **변경 사항:**
    * 기존 `yield`, `take` 메서드 제거 → `Ractor.pull` 방식의 **Ractor Port** 도입.
    * 메모리 공간을 철저히 격리하며, 불변 객체를 제외하고는 데이터를 공유하지 않아 락(Lock) 없이 안전하게 동작.
* **전망:** 2026년 중 실험적 상태를 탈피할 예정이며, CPU 집약적인 작업 처리에 혁신을 가져올 것으로 기대됩니다.

## 3. 기타 주요 개선 사항 및 파서(Parser) 혁신

### ■ 프리즘(Prism) 파서 도입
* 30년 된 기존 파서(parse.y)를 대체하는 차세대 파서.
* **성능:** 기존 대비 **2.56배** 빠르며, C99 표준으로 작성되어 외부 의존성이 없습니다.
* **이점:** IDE의 응답성 향상, CI 시간 단축 등 개발자 경험(DX)을 크게 개선합니다.

### ■ 코어 클래스 승격 및 문법 개선
* **Set & Parse:** 별도의 `require` 없이 바로 사용 가능한 코어 클래스로 승격되었습니다.
* **가독성 향상:** 논리 연산자(`&&`, `||`)를 줄의 시작 부분에 두어 복잡한 조건문을 영어 문장처럼 배치할 수 있게 되었습니다.
* **디버깅 강화:** `source_location` 메서드가 이제 행(Line)뿐만 아니라 열(Column) 정보까지 포함한 5개 요소를 반환합니다.

### ■ 타입 시스템 및 패키지 관리
* **RBS & Steep:** 루비 특유의 유연한 동적 타이핑을 유지하면서, 필요한 부분에만 점진적으로 타입을 추가하는 정적 분석 기능이 강화되었습니다.
* **번들러(Bundler) 4.0:** Gem 설치 시 **자동 병렬 빌드**를 지원하여 멀티코어 환경에서 설치 속도가 비약적으로 향상되었습니다.

## 4. 실무자를 위한 가이드 및 조언

1. **생산성과 성능의 조화:** 레일즈가 제공하는 내장 기능(로그인, 채팅, 캐시 등)에 YJIT의 성능이 더해져, 소수 인원으로 대규모 트래픽을 감당할 수 있는 최적의 스택이 되었습니다.
2. **보안의 강점:** 기본적으로 SQL 인젝션 및 XSS 방어 기제가 강력하여, 비개발자가 AI 코딩을 통해 서비스를 구축할 때 가장 안전한 선택지 중 하나입니다.
3. **업그레이드 전략:** 4.0은 브레이킹 체인지가 크지 않아 마이그레이션이 순조로울 것으로 예상되나, ZJIT와 루비 박스는 아직 실험적 단계이므로 프로덕션 적용 전 벤치마크 테스트가 필수입니다.

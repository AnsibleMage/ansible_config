# [학습 로드맵] 루비 온 레일즈(Rails 8): 기초부터 프로덕션 배포까지

* **출처:** [WeekdayCode 평일코딩](https://youtu.be/pZrWkJgmxl8)
* **핵심 주제:** Rails 8 기반의 풀스택 개발 학습법 및 프레임워크 철학
* **타겟:** 넥스트 JS(Next.js) 지옥에서 벗어나 안정적인 서비스를 만들고 싶은 개발자 및 1인 창업가

---

## 1. 왜 지금 '루비 온 레일즈'인가?

### ■ 넥스트 JS 지옥(Next.js Hell) 탈출
* 자바스크립트 생태계는 외부 의존성(Dependency)이 너무 많고 업데이트 속도가 지나치게 빨라 유지보수가 힘듦.
* 레일즈는 외부 의존성을 최소화하고 프레임워크 자체에서 대부분의 기능을 제공하는 **'안정성'**이 강점.

### ■ 생산성과 확장성
* "헬로 월드부터 기업 상장(IPO)까지" 스케일이 가능한 프레임워크 (예: Shopify, GitHub).
* 개인 제품 창업 시 가장 높은 생산성을 제공하며, 1인 개발자가 백엔드와 프론트엔드를 완벽하게 통제 가능.

---

## 2. 제임스가 추천하는 4단계 학습 로드맵

### Step 1: 공식 문서 및 데모 활용 (The Right Way)
* **Rails 공식 가이드:** 한국어 자료보다 최신화가 잘 된 영어 공식 문서를 추천.
* **데모 영상:** 레일즈 창시자(DHH)가 직접 진행한 **Rails 8 데모 영상**을 통해 전체적인 흐름 파악.
* **Getting Started 가이드:** MVC 패턴, 액티브 레코드(Active Record), 라우팅 등 핵심 개념을 스토어 만들기 예제로 학습.

### Step 2: 체계적인 영상 강좌 (Typecraft 추천)
* **유튜브 채널 'Typecraft':** 레일즈 8 비기너 코스를 제공.
* **학습 포인트:** 단순히 코드를 따라치는 것이 아니라, 어떤 클래스와 모듈이 어떤 역할을 하는지(와스, 미들웨어, 뷰의 사이클) 이해하는 것이 중요.
* **배포 경험:** 카말(Kamal) 모듈을 통한 배포와 디지털 오션(Digital Ocean) 인스턴스 활용법 익히기.

### Step 3: 실전 소스 코드 분석 (ONCE 프로젝트)
* **37signals의 'Writebook':** 실제 유료로 판매되던 사스(SaaS)였으나 현재 무료로 소스 코드가 공개됨.
* **가치:** 가장 '레일즈답게' 작성된 프로덕션 급 코드를 직접 로컬에서 실행하고 분석 가능.
* **분석 대상:** 인증(Authentication), 세션 관리, 모델 설계 방식 등.

### Step 4: 심화 및 유료 강의 (Udemy & API Docs)
* **Udemy:** 'Rails 8 & Hotwire' 관련 강의 추천. (단, 최근 레일즈 기본 인증 모듈이 생겼으나 여전히 많이 쓰이는 'Devise' 잼 위주 강의가 많음)
* **공식 API 문서:** 특정 기능 구현 시 AI에게 묻기 전, 공식 API 문서(특히 Active Record 부분)를 통해 정확한 동작 원리 확인.

## 3. 루비 온 레일즈의 핵심 기술 스택

* **Active Record (ORM):** SQL을 직접 쓰지 않고 객체 지향적으로 DB와 통신. 설계 시 모델 정의부터 시작하는 것이 정석.
* **Hotwire:** 자바스크립트를 최소화하면서도 SPA(단일 페이지 앱)와 같은 빠른 사용자 경험 제공.
* **Kamal:** 특정 클라우드 서비스(Vercel 등)에 종속되지 않고 인스턴스에 직접 배포하여 비용을 절감하는 도구.

---

## 4. 실무자를 위한 철학적 조언

1. **DB 친화적 설계:** 화려한 UI보다 모델과 DB의 관계, 데이터의 안정적인 처리가 시스템 운영의 핵심.
2. **최신 스택에 매몰되지 말 것:** PHP와 jQuery로도 거대한 수익을 내는 개발자(예: Peter Levels)가 있듯이, 도구의 속도보다 기능을 찍어내는 '생산성'이 중요.
3. **네트워크가 가장 느리다:** 언어의 속도 차이는 웹 서비스 수준에서 체감하기 어려움. 루비는 웹 개발에 충분히 빠름.
4. **AI 에이전트 코딩의 한계:** AI가 코드를 짜주더라도 토큰 비용 문제나 API 소진 시 대응을 위해 개발자가 프레임워크의 동작 원리를 이해하고 있어야 함.

# 구체적인 프롬프트 사례 모음

## 📝 조사 개요

**포함 내용:**
- 효과적인 TDD 프롬프트 10개 이상
- 도구별 최적화 전략
- 안티패턴 및 해결책
- 실무 적용 사례

**기반 자료:**
- Stack Overflow TDD 질문 (상위 50개)
- 개발자 블로그 및 Medium 기사
- 공식 도구 가이드
- 연구 논문의 프롬프트 예시

---

## 🎯 핵심 프롬프팅 원칙

### 성공적인 TDD 프롬프트 5가지 요소

1. **명확한 의도 선언**
   - "먼저 테스트를 작성"
   - "RED-GREEN-REFACTOR 사이클 따르기"

2. **구체적인 요구사항**
   - 함수 서명
   - 입력/출력 예시
   - 엣지 케이스

3. **테스트 우선 강조**
   - 테스트가 명세 역할
   - 테스트 통과가 완료 기준

4. **단계별 진행**
   - 한 번에 하나의 테스트
   - 최소 구현
   - 리팩토링

5. **검증 지표**
   - 커버리지 목표 (예: 80%)
   - 모든 테스트 통과
   - 코드 품질 확인

## 📚 프롬프트 카테고리별 예시

### 카테고리 1: 기본 TDD 시작

#### 프롬프트 1.1: 간단한 함수
```
"작은 함수를 TDD로 작성해줘.

요구사항:
- 함수명: isPalindrome
- 입력: 문자열
- 출력: boolean
- 예시: isPalindrome('racecar') → true
- 예시: isPalindrome('hello') → false

1단계: 실패하는 테스트를 먼저 작성
2단계: 최소한의 구현으로 테스트 통과
3단계: 코드 리팩토링
"
```

**효과:** 매우 높음 ⭐⭐⭐⭐⭐
- 명확한 단계 진행
- 구체적인 예시
- 작은 스코프
- 모든 AI 모델에 효과적

---

#### 프롬프트 1.2: 에러 처리 포함
```
"TDD로 작은 함수를 만들어줘.

함수: divideNumbers(a, b) → number

테스트 케이스:
- divideNumbers(10, 2) → 5
- divideNumbers(10, 0) → Error 발생
- divideNumbers(-10, 2) → -5

프로세스:
1. 위 케이스를 모두 커버하는 테스트 먼저 작성
2. 테스트를 통과하는 최소 구현
3. 리팩토링

사용 언어: JavaScript
테스트 프레임워크: Jest
"
```

**효과:** 높음 ⭐⭐⭐⭐
- 에러 케이스 명시
- 구체적인 기술 스택
- 단계별 진행

### 카테고리 2: 중급 - 복잡한 함수

#### 프롬프트 2.1: 컬렉션 처리
```
"TDD로 함수를 작성해줘: filterAndSort

요구사항:
- 숫자 배열 입력받기
- 짝수만 필터링
- 내림차순 정렬
- 빈 배열 처리

테스트 케이스:
- [3, 1, 4, 1, 5, 9, 2, 6] → [6, 4, 2]
- [1, 3, 5] → [] (짝수 없음)
- [] → []

진행 방식: TDD (테스트 먼저)
언어: Python
"
```

**효과:** 중간-높음 ⭐⭐⭐⭐
- 복잡도 증가
- 여러 테스트 케이스
- 엣지 케이스 포함

---

#### 프롬프트 2.2: 클래스 설계
```
"TDD로 Calculator 클래스를 설계하고 작성해줘.

요구사항:
- add, subtract, multiply, divide 메서드
- 현재 결과를 저장하는 상태
- 체이닝 가능 (fluent interface)
- 모든 연산에 타입 검증

예시 사용:
calc = Calculator()
result = calc.add(5).multiply(2).subtract(3).getValue() // 7

테스트:
- 각 메서드별 10개 이상의 테스트
- 에러 케이스 포함
- 상태 변경 검증

TDD 엄격히 따르기: RED → GREEN → REFACTOR
"
```

**효과:** 높음 ⭐⭐⭐⭐
- 설계 복잡도
- 상태 관리
- API 설계

### 카테고리 3: 고급 - 프롬프트 엔지니어링

#### 프롬프트 3.1: Code-Aware Prompting (SymPrompt 방식)
```
"TDD로 함수를 작성해줘. (Code-Aware 방식)

먼저 코드 분석:
- 이 함수가 어디서 사용될지 생각하기
- 의존성 확인
- 엣지 케이스 식별

함수 요구사항: mergeArrays

현재 코드:
```
function processData(input) {
  const arrays = parseInput(input);
  const merged = mergeArrays(arrays);  // ← 이 함수 구현하기
  return formatOutput(merged);
}
```

테스트 먼저:
1. 실행 경로 분석 후 테스트 작성
2. 각 입력 유형 고려
3. 부작용(side effects) 확인

TDD: 실패 → 통과 → 리팩토링
"
```

**효과:** 매우 높음 ⭐⭐⭐⭐⭐
- 코드 컨텍스트 활용
- 5배 향상 가능 (연구 결과)
- 실행 경로 기반

---

#### 프롬프트 3.2: 커버리지 유도 (CoverUp 방식)
```
"TDD로 다음 함수를 작성해줘.

현재 커버리지: 0%
목표 커버리지: 80% 이상 (라인 + 브랜치)

함수: validateEmail(email) → { valid: boolean, errors: string[] }

요구사항:
- 이메일 형식 검증
- 도메인 유효성
- 길이 확인
- 특수 문자 처리

프로세스:
1. 모든 경로를 커버하는 테스트 먼저 작성
2. 라인 커버리지 목표: 100%
3. 브랜치 커버리지 목표: 80%
4. 최소 구현으로 테스트 통과
5. 리팩토링

테스트 케이스 체크리스트:
- [ ] 유효한 이메일
- [ ] '@' 없는 경우
- [ ] 도메인 없는 경우
- [ ] 특수 문자 포함
- [ ] 너무 긴 이메일
- [ ] 빈 문자열

언어: TypeScript
"
```

**효과:** 매우 높음 ⭐⭐⭐⭐⭐
- 커버리지 명시적 추구
- 80%+ 커버리지 달성 가능
- 브랜치 커버리지 강조

### 카테고리 4: 안티패턴 및 해결책

#### 안티패턴 1: 너무 큰 단계
**❌ 나쁜 프롬프트:**
```

```

**✅ 좋은 프롬프트:**
```
"TDD로 작은 함수부터 시작해줘: generateStorageKey()

- 사용자 ID 받기
- 타임스탬프와 결합
- 고유 키 생성

테스트 2-3개로 시작하기
"
```

#### 안티패턴 2: 모호한 요구사항
**❌ 나쁜 프롬프트:**
```
"좋은 함수를 만들어줘"
```

**✅ 좋은 프롬프트:**
```
"TDD로 함수를 만들어줘:

함수명: isValidPassword
입력: string
출력: { valid: boolean, reason?: string }

규칙:
- 최소 8자
- 대문자 1개 이상
- 숫자 1개 이상
- 특수문자 1개 이상

테스트 먼저 작성하기
"
```

#### 안티패턴 3: AI의 "큰 도약" 방지
**❌ 나쁜 프롬프트:**
```
"전체 계산 엔진을 TDD로 작성해줘"
```

**✅ 좋은 프롬프트:**
```
"TDD의 RED-GREEN-REFACTOR 사이클을 엄격히 따라줘.

첫 번째 단계:
1. add 메서드만 구현하기
2. 테스트 1개: add(2, 3) → 5

완료 후 다음 단계로 진행하기
"

"TDD로 함수를 작성해줘. Claude의 강점을 활용해줘.

당신의 강점:

단계별로:
1. 먼저 테스트 전략 설명

"
```

### 카테고리 6: 실무 적용 패턴

#### 패턴 1: 레거시 코드 테스트 작성
```
"이 레거시 함수에 TDD로 테스트를 추가해줘.

기존 함수:
```javascript
function calculateTotal(items) {
  let total = 0;
  for (let i = 0; i < items.length; i++) {
    total += items[i].price * items[i].quantity;
  }
  return total;
}
```

하지만:
- 할인 규칙 추가 필요
- 세금 포함
- 유효성 검증

접근 방식:
1. 기존 함수 동작하는 테스트 먼저 작성
2. 새 기능별로 테스트 추가
3. 리팩토링으로 개선

TDD로 진행해줘
"
```

| 프롬프트 유형 | 효과도 | 도구별 | 주의사항 |

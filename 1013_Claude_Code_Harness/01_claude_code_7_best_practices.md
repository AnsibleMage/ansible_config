# Claude Code 창시자 × 해커톤 우승자 — 7가지 공통 사용법

## 개요

Claude Code 창시자 **Boris**와 Anthropic 공식 해커톤 우승자가 공통적으로 실천하는 **7가지 사용법**을 정리한 문서. 두 전문가의 접근법이 겹치는 지점이 곧 **정석적 방법론**이라는 관점에서 분석.

---

## 카테고리별 요약

| # | 카테고리 | 핵심 요약 | 누가 강조 |
|---|---------|----------|----------|
| 1 | **병렬 작업** | 터미널 3~5개 워크트리로 동시 작업 → 5시간→1~2시간 | 창시자(5개) + 우승자 |
| 2 | **CLAUDE.md 투자** | 실수 발생 시 기록 → 학습 루프 자동화 → 세션 간 기억 유지 | 양쪽 공통 |
| 3 | **플랜 모드** | 코드 작성 전 계획 수립 → 리뷰("시니어라면 허점은?") → 구현 | 창시자 팀 프롬프트 공개 |
| 4 | **서브 에이전트** | 오케스트레이터 + 전문가 + 실행자 3계층 구조 | 우승자(13개 에이전트) |
| 5 | **검증 루프** | "이게 된다는 걸 증명해 봐" → 품질 2~3배 향상 | **창시자가 꼽은 1순위** |
| 6 | **커스텀 스킬** | 하루 2회+ 반복 업무 → 슬래시 커맨드로 자동화 | 우승자(40개 스킬/10개월) |
| 7 | **훅 자동화** | PreToolUse/PostToolUse/Stop → CI 실패 10% 원천 차단 | 창시자 팀 데이터 |

## 상세 분석

### 1. 병렬 작업 (Parallel Work)

| 항목 | 내용 |
|------|------|
| **방법** | 터미널 3~5개를 워크트리(worktree)로 열어 각기 다른 작업 동시 수행 |
| **효과** | 직렬(순차) 5시간 → 병렬 1~2시간 |
| **적용 예시** | 같은 프로젝트 내 세부 분업 (API 설계 / 테스트 작성 / 문서 작성) 또는 각각 다른 프로젝트 |
| **핵심 전환** | 직렬 구조(하나 끝나고 → 다음) → 병렬 구조(동시 다발적 진행) |

> **창시자 Boris**: 5개 병렬 에이전트 사용

---

### 2. CLAUDE.md 투자

| 항목 | 내용 |
|------|------|
| **역할** | Claude의 뇌 = 업무 매뉴얼. 각 폴더/프로젝트의 운영 가이드 |
| **핵심 전략** | 실수 발생 → CLAUDE.md에 기록 → 동일 실수 반복 방지 |
| **왜 중요한가** | 새 터미널/세션 시작 시 기억 리셋 → CLAUDE.md가 기억 복원 역할 |
| **학습 루프** | 실수 기록 축적 → 자동 참조 → 실수 감소 → 품질 향상 |

> **공통점**: 실수할 때마다 기록 → 학습 루프가 스스로 작동되는 구조

---

### 3. 플랜 모드 (Plan Mode)

| 항목 | 내용 |
|------|------|
| **기존 방식** | 계획 없이 "만들어줘" → 코딩 → 버그 → 수정 → 구조 문제 → 산으로 |
| **플랜 모드** | 상세 계획 수립 → Claude가 질문 → 사용자 검토 → 승인 후 구현 |
| **창시자 팀 프롬프트** | "네가 시니어 엔지니어라면 이 계획의 허점은 뭐라고 생각해?" |
| **확장 패턴** | Claude A가 계획 → C응laude B가 검토(허점 발견) → 허점 보완 후 구현 |

> **핵심**: 계획만 잘 세워도 뒤의 것들은 쉬워진다

---

### 4. 서브 에이전트 활용

| 항목 | 내용 |
|------|------|
| **구조** | 메인 에이전트(관리자/오케스트레이터) + 서브 에이전트(전문가/실행자) |
| **비유** | 식당 사장님(지휘) + 서빙/주방/접객(실행) |
| **해커톤 우승자 구조** | Layer 1: 플래너+오케스트레이터 → Layer 2: 전문가(코드리뷰/보안/설계/테스트) → Layer 3: 실행자 13개 |
| **발표자 운영** | 80개 → 다이어트 → 8~9개 (불필요 에이전트 제거로 토큰 절약) |

> **핵심**: 에이전트 수보다 **어떤 에이전트를 어떻게 쓰느냐**가 중요

---

### 5. 검증 루프 (Verification Loop) — 창시자 선정 1순위

| 항목 | 내용 |
|------|------|
| **효과** | 품질 **2~3배** 향상 (창시자 팀 공식 발언) |
| **루프 구조** | 코드 생성 → 테스트 실행 → 실패 → 수정 → 검증 통과 (반복) |
| **창시자 프롬프트** | "이게 된다는 걸 증명해 봐" |
| **우승자 프롬프트** | "최종 목표를 주고, 이게 되면 성공이야" |
| **공통점** | 명확한 성공 기준 제시 → 자가 검증 자동화 |

> **Boris**: "딱 하나만 고르라면? **검증 루프**"

---

### 6. 커스텀 스킬 (Custom Skills)

| 항목 | 내용 |
|------|------|
| **개념** | 슬래시(/) + 단어 하나로 자동 실행되는 반복 작업 시스템 |
| **만드는 법** | 작업 수행 후 "지금까지 작업했던 내용을 스킬로 만들어 줘" |
| **우승자 규모** | 13개 에이전트 + **40개 스킬** (10개월 축적) |
| **성과** | 기능 완성 속도 65% 향상, 코드 리뷰 이슈 감소, 테스트 커버리지 향상 |
| **Boris 규칙** | **하루 2회 이상 반복되는 업무 → 무조건 스킬로** |

> **핵심**: 오래 사용하며 누적될수록 **나의 자산**이 됨

---

### 7. 훅 자동화 (Hook Automation)

| 항목 | 내용 |
|------|------|
| **비유** | 현관문 센서 — 문이 열리면 자동으로 불이 켜지는 구조 |
| **PreToolUse** | 도구 실행 전 — 위험한 명령 차단 |
| **PostToolUse** | 코드 실행 후 — 자동 코드 정리(들여쓰기, 공백 제거) |
| **Stop** | 작업 종료 시 — 디버그 코드/실수 잔재 검출 |
| **창시자 팀 데이터** | CI/CD 실패 중 **10%가 단순 포맷 문제** → PostToolUse 훅으로 **0%**로 감소 |

> **핵심**: 실수를 시스템으로 원천 차단

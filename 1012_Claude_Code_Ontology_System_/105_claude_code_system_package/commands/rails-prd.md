# /rails-prd - PRD 자동 생성

사용자 요구사항을 분석하여 PRD(Product Requirements Document)를 자동 생성합니다.

## 트리거
- "PRD 만들어줘", "요구사항 문서", "기획서 작성"

## 실행 단계

### 1. 요구사항 분석

현재까지의 대화에서 다음을 추출:
- 핵심 기능 요구사항
- 암묵적 요구사항 (인증, 보안 등)
- 비기능 요구사항
- 제약 조건

### 2. 4-Layer 분석 적용

| Layer | 분석 내용 |
|-------|----------|
| Lexical | 키워드, 도메인 용어 추출 |
| Syntactic | 문장 구조, 요청 유형 분석 |
| Discourse | 컨텍스트, 이전 대화 반영 |
| Pragmatic | 암묵적 의도 파악 |

### 3. PRD 문서 생성

`docs/PRD.md` 파일 생성:

```markdown
# PRD: [프로젝트명]

## 1. 개요
### 1.1 제품 비전
### 1.2 목표 사용자
### 1.3 성공 지표

## 2. 기능 요구사항
### 2.1 [기능 그룹 1]
#### US-001: [사용자 스토리]
**As a** [역할]
**I want to** [행동]
**So that** [이유]

**수용 기준**:
- [ ] [기준 1]
- [ ] [기준 2]

**우선순위**: P0

### 2.2 [기능 그룹 2]
...

## 3. 비기능 요구사항
### 3.1 성능
### 3.2 보안
### 3.3 확장성

## 4. 데이터 모델
### 4.1 엔티티 정의
### 4.2 관계 다이어그램

## 5. 화면 흐름
### 5.1 사용자 여정
### 5.2 주요 화면

## 6. 제약사항 및 가정

## 7. 마일스톤

## 8. 버전 이력
```

### 4. 사용자 스토리 작성 규칙

각 사용자 스토리는 다음 형식을 따름:

```markdown
#### US-XXX: [제목]

**As a** [역할]
**I want to** [행동]
**So that** [이유/가치]

**수용 기준**:
- [ ] Given [사전조건] When [행동] Then [결과]
- [ ] [추가 기준]

**우선순위**: P0 (필수) / P1 (중요) / P2 (선택)
```

### 5. 데이터 모델 정의

각 엔티티는 다음 형식으로 정의:

```markdown
#### [Entity Name]

| 필드 | 타입 | 제약조건 | 설명 |
|------|------|---------|------|
| id | bigint | PK | 기본키 |
| [필드] | [타입] | [제약] | [설명] |
```

### 6. 검토 요청

PRD 생성 후 사용자에게 검토 요청:

```
PRD를 생성했습니다: docs/PRD.md

요약:
- 기능 요구사항: [N]개 사용자 스토리
- 데이터 모델: [N]개 엔티티
- 마일스톤: [N]개

확인해주시면 작업계획서를 생성합니다.

질문:
1. [명확히 해야 할 사항 1]
2. [명확히 해야 할 사항 2]
```

### 7. 수정 반영

사용자 피드백 시:
1. 해당 섹션 업데이트
2. 버전 이력 추가
3. 변경 사항 요약 제공

## 템플릿 위치

`~/.claude/templates/rails8/PRD_Template.md`

## 예시

**입력**: "블로그가 필요해. 마크다운으로 글 쓰고, 댓글도 있으면 좋겠어."

**출력**:
- docs/PRD.md 생성
- 기능: 사용자 인증, 글 CRUD, 댓글, 마크다운 렌더링
- 데이터 모델: User, Article, Comment
- 화면: 홈, 글 목록, 글 상세, 로그인, 글 작성

# Memory Save Protocol System

> Claude Code 응답 완료 프로토콜 및 메모리 저장 시스템

## 개요

이 시스템은 Claude Code 세션에서 의미 있는 작업이 완료될 때마다 자동으로 메모리를 저장하여 지식을 축적하는 프로토콜입니다.

### 왜 필요한가?

- **지식 연속성**: 세션 간 컨텍스트 유지
- **학습 축적**: 분석, 설계, 인사이트 기록
- **중복 방지**: 동일 주제 자동 통합
- **검색 가능**: 체계적인 파일명 규칙

## 응답 완료 프로토콜

### 실행 조건

**모든 의미 있는 작업 완료 시, 응답 마지막에 실행**

### 플로우

```
작업 완료
    ↓
┌─────────────────────────────┐
│ 1. 최근 메모리 3개 읽기      │
│    (중복 방지)               │
└─────────────────────────────┘
    ↓
┌─────────────────────────────┐
│ 2. 저장 여부 판단            │
│ - 새로운 지식/인사이트?      │
│ - 중요한 결정/변경?          │
│ - 이전 메모리와 중복?        │
└─────────────────────────────┘
    ↓
┌───────┴───────┐
│               │
중복            새 내용
↓               ↓
기존 파일       새 파일 생성
업데이트        YYMM_SEQ_keyword
    ↓               ↓
    └───────┬───────┘
            ↓
💾 메모리 저장 완료
    ↓
🎵 완료! 다음은 뭘 할까요?
```

### 저장 기준

| 저장 O | 저장 X |
|--------|--------|
| 분석/설계 결과 | 단순 Q&A |
| 새로운 구현 | 파일 읽기만 |
| 중요한 결정 | 간단한 수정 |
| 학습/인사이트 | 반복 작업 |

## 메모리 저장소

### 위치

```
~/.claude/memory/
```

### 파일명 규칙

```
YYMM_SEQ_keyword.md
```

| 구성 요소 | 설명 | 예시 |
|----------|------|------|
| **YYMM** | 연월 (2자리+2자리) | `2602` = 2026년 2월 |
| **SEQ** | 월별 시퀀스 (001~999, 매월 리셋) | `015` |
| **keyword** | 작업 키워드 (snake_case) | `rails8_analysis` |

### 파일명 예시

```
2602_001_claude_md_update.md     # 2월 첫 번째
2602_015_rails8_analysis.md      # 2월 15번째
2603_001_new_project.md          # 3월 첫 번째 (리셋)
```

### 장점

- **무제한 확장**: 매월 999개, 리셋으로 무한
- **시간 순서**: YYMM으로 시간순 정렬
- **시퀀스 추적**: SEQ로 월별 작업량 파악
- **월별 아카이브**: 자연스러운 폴더 분리 가능

## 중복 방지 규칙

> **저장 전 반드시 최근 메모리 3개를 읽어 중복 확인**

### 판단 기준

| 상황 | 행동 |
|------|------|
| **동일 주제** | 기존 파일에 `## 추가 내용` 섹션으로 업데이트 |
| **새로운 주제** | 새 파일 생성 (YYMM_SEQ_keyword) |
| **세션 내 여러 번 저장** | 하나로 통합 |

### 체크 방법

```bash
# 최근 메모리 3개 확인
ls -lt ~/.claude/memory/ | head -4
```

## Stop Hook vs 지침 기반 (설계 결정)

### 왜 Stop Hook을 사용하지 않는가?

| 구분 | Stop Hook | 지침 기반 |
|------|-----------|----------|
| **실행 시점** | 응답 완료 후 | 응답 내에서 |
| **Claude 접근** | 불가 (스키마 제한) | 가능 |
| **메모리 저장** | 추가 작업 불가 | 자유롭게 가능 |
| **유연성** | 낮음 | 높음 |

### 결론

Stop Hook은 응답 완료 후 실행되어 Claude가 추가 작업을 수행할 수 없습니다.
따라서 **CLAUDE.md 지침 기반**으로 응답 마지막에 메모리 저장을 수행합니다.

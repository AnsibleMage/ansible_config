# 연구 보고서: 에이전트 체인 및 트리거 시스템

**날짜**: 2026-01-24
**주제**: 고급 체인 및 트리거 시스템을 통한 Antigravity 글로벌 설정(`GEMINI.md`) 강화
**출처**: Anthropic (Claude), Google (Gemini), Microsoft (AutoGen), 학술 논문 (ReAct, MAS)

---

## 1. 개요 (Executive Summary)
효율적인 다중 에이전트 시스템은 **트리거(Trigger)**(의도 감지)와 **체인(Chain)**(워크플로우 오케스트레이션)이라는 두 가지 핵심 요소에 의존합니다.
최신 연구에 따르면 단순한 순차적 체인에서 **동적 의미론적 라우팅(Dynamic Semantic Routing)** 및 **병렬/하이브리드 실행(Parallel/Hybrid Execution)** 패턴으로 이동하는 추세입니다.
Antigravity가 "글로벌 표준"으로 자리 잡기 위해서는, 단순히 고정된 순서가 아니라 "인지(Perceive) - 사고(Think) - 행동(Act) - 검증(Verify)"하는 적응형 워크플로우를 지원해야 합니다.

---

## 2. 트리거 시스템 (The "Brain")

### A. 트리거의 진화
1.  **키워드 매칭 (1세대)**: 단순한 `if "code" in input: call Developer` 방식.
    *   *한계*: 뉘앙스를 파악하지 못함 (예: "이 로직 좀 검토해줘"는 단순 리뷰어가 아닌 아키텍트가 필요할 수 있음).
2.  **의미론적 라우팅 (2세대 - 권장)**:
    *   벡터 임베딩을 사용하여 사용자의 의도를 "에이전트 클러스터"에 매핑.
    *   *적용 예*: "이거 좀 더 빠르게 만들어줘" → `성능 최적화 체인` 발동 (개발자 + 프로파일러).
3.  **이벤트 기반 트리거 (3세대)**:
    *   시스템 상태 변화가 에이전트를 트리거 (예: "테스트 실패" 이벤트가 자동으로 `디버거 에이전트`를 호출).

### B. 업계 모범 사례
*   **Microsoft AutoGen**: `GroupChatManager`를 사용하여 "화자 선택(Speaker Selection)" 전략(라운드 로빈, 무작위, 또는 LLM 기반)을 동적 트리거로 활용합니다.
*   **Google Gemini**: 에이전트 정의 내의 `description` 필드를 의미론적 라우터의 핵심 API로 강조합니다.

### C. Antigravity를 위한 제안
**이중 레이어 트리거 시스템(Dual-Layer Trigger System)** 구현:
1.  **Fast Path (키워드)**: 신뢰도가 높고 구체적인 명령어 (예: `/architect`, `/설계`).
2.  **Slow Path (의미론적)**: 자연어 의도 분석 (예: "확장성이 좀 걱정되는데..." -> 아키텍트 + 복잡성 해결사 트리거).

## 3. 체인 시스템 (The "Body")

### A. 실행 패턴
| 패턴 | 설명 | 적합한 용도 |
| :--- | :--- | :--- |
| **순차적 (ReAct)** | `Agent A -> Agent B -> Agent C` | 선형적 작업 (예: 계획 -> 코드 -> 리뷰). |
| **병렬 (Map-Reduce)** | `[Agent A, Agent B, Agent C] -> Aggregator` | 연구, 브레인스토밍 (예: 3가지 다양한 관점 분석). |
| **하이브리드 / 중첩** | `(A || B) -> C -> Loop(D)` | 복잡한 시스템 설계 (예: 프론트+백엔드 개발 -> 통합 -> 테스트 루프). |
| **평가자-최적화자** | `Generator -> Evaluator -> (Loop if < Score)` | 고품질 코드 생성 (Claude가 선호하는 패턴). |

### B. "보편적 에이전트 루프" (Anthropic)
효과적인 체인은 강력한 내부 루프를 따릅니다:
1.  **인지 (Perceive)**: 맥락을 수집합니다.
2.  **사고 (Think)**: 접근 방식에 대해 추론합니다 (Chain of Thought).
3.  **행동 (Act)**: 도구를 사용합니다.
4.  **검증 (Verify)**: 성공 기준과 결과를 대조합니다. *단순 체인에서 자주 누락되는 결정적인 단계입니다.*

### C. Antigravity를 위한 제안
`GEMINI.md`에 이러한 패턴에 대응하는 "표준 체인"을 정의합니다:
*   **개발 체인 (DevChain)**: `아키텍트(계획) -> 개발자(코드) -> 리뷰어(검증) -> (실패 시 루프)`
*   **사고 체인 (ThinkChain)**: `인사이트(탐구) -> [다차원 + 연결](병렬 분석) -> 현자(종합)`

## 4. GEMINI.md 업그레이드 제안

이 연구를 바탕으로 글로벌 설정에 다음과 같은 개선 사항을 제안합니다:

### 1. 고급 트리거 정의
트리거를 단일 에이전트가 아닌 **의도 카테고리(Intent Categories)** 에 매핑합니다.
```markdown
| 의도 카테고리 | 주 담당 스킬 | 지원 스킬 |
| :--- | :--- | :--- |
| **"시스템이 느려"** | `품질 리뷰어` (성능) | `복잡성 해결사` |
| **"새 기능 추가해줘"** | `요구사항 분석가` | `시스템 아키텍트` |
```

### 2. 명시적 워크플로우 정의
"체인 시스템" 섹션을 시각화 가능한 경로로 공식화합니다.
*   **순차**: `->`
*   **병렬**: `||`
*   **루프**: `(Loop Condition)`

### 3. "품질 게이트(Quality Gate)" 규칙
**검증 단계 없이는 어떤 체인도 완료되지 않음**을 전역 규칙으로 추가합니다.
*   *연구 근거*: 전담 검증/평가 노드가 있는 시스템이 훨씬 더 나은 성능을 보임 (Google/Anthropic 결과).
*   *설정*: 개발 체인은 항상 `품질 리뷰어`로 종료해야 합니다.

### 4. 의미론적 컨텍스트 공유
Google ADK의 "상태 관리" 원칙 채택:
*   정보 손실을 방지하기 위해 에이전트 간 **표준 컨텍스트 핸드오프 포맷**을 정의합니다.
